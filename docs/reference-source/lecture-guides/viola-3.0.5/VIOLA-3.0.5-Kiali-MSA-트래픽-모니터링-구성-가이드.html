VIOLA 3.0.5

Kiali MSA 트래픽 모니터링

구성 및 시연 가이드 (biz 클러스터 / academy 네임스페이스)

항목 내용
대상 환경 VIOLA 3.0.5, biz 클러스터 (edu-bf305-biz-1~3), 네임스페이스 academy
시연 구성 istio-gateway → msa-a → msa-b → msa-c (필요 시 msa-b v2 추가)
작성 기준 3.0.6 가이드를 3.0.5 환경에 맞게 조정한 버전. 실제 3.0.5 클러스터에서 적용하고 호출 확인까지 마침

1. 개요

Istio 사이드카가 붙은 애플리케이션 사이의 호출을 Kiali 그래프로 보여주는 시연입니다. nginx 파드 세 개를 a → b → c 순서로 연결하고, 부하 파드로 트래픽을 흘려 보내면 서비스 간 호출 관계, 요청 속도, 응답 시간이 그래프에 나타납니다.

3.0.6에서 먼저 구성한 시연을 3.0.5에 맞게 옮겼으며, 이 문서는 3.0.5에서 달라지는 부분과 실제로 겪은 문제를 중심으로 정리했습니다.

4. 구성 절차

4.1 구성도

msa-load 파드(사이드카 없음)가 약 2 req/s로 istio-gateway 서비스를 호출하고, Gateway msa-gateway와 VirtualService msa-demo를 거쳐 msa-a → msa-b → msa-c 순서로 전달됩니다. 맥에서 직접 호출하는 경로(NodePort 30223, msa_demo_traffic_305.sh)는 선택 사항입니다.

4.2 academy 사이드카 주입 활성화

academy 라벨이 istio-injection=disabled이면 파드에 sidecar.istio.io/inject: "true"를 달아도 주입되지 않습니다. 시연 전에 enabled로 바꿉니다.

kubectl label ns academy istio-injection=enabled --overwrite
kubectl get ns academy --show-labels

주의: 주입은 파드가 새로 만들어질 때 적용됩니다. academy에 이미 있는 다른 파드(user0-nginx-…, academy-nginx-daemonset-… 등)는 재시작될 때 사이드카가 붙으므로, 시연 직전에 재시작하지 않도록 합니다. 문제가 생기면 라벨을 disabled로 되돌립니다.

4.3 매니페스트 복사

매니페스트는 msa-demo-305.yaml(앱, Gateway, VirtualService)과 msa-load-305.yaml(부하 파드)이 기본이고, 선택 구성으로 msa-b-v2-305.yaml(msa-b의 두 번째 버전)과 msa-hpa-305.yaml(HPA 시연용, 별도 HPA 시연 가이드 참고)이 함께 제공됩니다. 복사 스크립트는 네 파일을 모두 복사하며, 시연 앱 배포(4.4)에는 앞의 두 파일만 사용합니다. 전체 내용은 부록에 있습니다. 맥에서 복사 스크립트를 실행하고 비밀번호를 입력합니다.

bash msa_push_305.sh      # root@192.0.2.48:~/ 로 네 파일 복사

4.4 적용

적용 전에 CRD와 라벨을 확인하고 두 파일을 적용합니다.

kubectl get ns academy --show-labels
kubectl get crd virtualservices.networking.istio.io
kubectl apply -f ~/msa-demo-305.yaml && kubectl apply -f ~/msa-load-305.yaml

정상이면 service 3개, configmap 3개, deployment 4개(msa-a, b, c, load), gateway 1개, virtualservice 1개가 생성됩니다(총 12개).

4.5 사이드카 확인

kubectl -n academy get pods -l demo=kiali-msa -o custom-columns=NAME:.metadata.name,READY:.status.containerStatuses[*].ready,CONTAINERS:.spec.containers[*].name

msa-a, msa-b, msa-c 파드의 CONTAINERS에 nginx, istio-proxy가 함께 보여야 합니다. msa-load는 의도적으로 사이드카가 없어 load만 보입니다.

4.6 호출 확인

curl -s -H "Host: okestro-academy-msa-demo.com" http://192.0.2.48:30223/

msa-c ok가 응답되면 a → b → c 체인이 정상입니다.

5. 트러블슈팅: 426 Upgrade Required

증상: 게이트웨이로 호출하면 HTTP 426 Upgrade Required가 반환되고 msa-c ok가 나오지 않습니다. 응답 헤더는 server: istio-envoy입니다.

원인: nginx의 proxy_pass는 업스트림 호출에 기본적으로 HTTP/1.0을 사용합니다. Istio 사이드카(Envoy)가 HTTP/1.0 요청을 거부하면서 426을 돌려줍니다.

해결: msa-a-conf와 msa-b-conf의 proxy_pass 앞에 proxy_http_version 1.1; 을 추가합니다. ConfigMap을 수정해도 nginx는 설정을 자동으로 다시 읽지 않으므로 Deployment를 재시작해야 합니다.

kubectl apply -f ~/msa-demo-305.yaml
kubectl -n academy rollout restart deploy msa-a msa-b
kubectl -n academy rollout status deploy msa-a msa-b

확인 요령: apply 결과에 configmap/msa-a-conf configured가 보여야 수정본이 적용된 것입니다. unchanged로 나오면 서버로 복사한 파일이 이전 버전이라는 뜻이므로 복사 스크립트가 끝까지 실행되었는지(비밀번호 입력 대기에서 멈추지 않았는지) 확인합니다.

6. 시연 진행

6.1 Kiali 화면

  • VIOLA 3.0.5 포털의 모니터링 메뉴에서 트래픽 모니터링으로 들어가 네임스페이스 academy를 선택합니다.

  • 그래프에 istio-gateway → msa-a → msa-b → msa-c가 나타나는지 확인합니다. 처음 나타나기까지 1~2분 걸릴 수 있습니다.

  • 조회 시간 범위는 Last 5m 정도가 안정적입니다. Display에서 Traffic Animation, Response Time 등을 켜면 시연 효과가 좋습니다.

  • Kiali는 요청이 실제로 흐른 워크로드만 그립니다. 사이드카가 있어도 요청이 없으면 나타나지 않으며, Idle Nodes 옵션으로 확인할 수 있습니다.

6.2 트래픽 켜기/끄기

msa-load 파드 하나가 약 2 req/s를 보냅니다. replica 수로 조절합니다.

동작 명령
멈추기 kubectl -n academy scale deploy msa-load --replicas=0
켜기 kubectl -n academy scale deploy msa-load --replicas=1
늘리기 (약 6 req/s) kubectl -n academy scale deploy msa-load --replicas=3

멈춘 뒤에도 그래프의 선이 사라지는 데 1~2분 걸립니다. 멈추는 장면을 보여주려면 시간 범위를 Last 1m로 줄여 둡니다. 더 많은 요청이 필요하면 맥에서 msa_demo_traffic_305.sh [초당요청수] [지속시간(초)]를 실행합니다.

6.3 msa-b v2 추가 (선택)

msa-b를 버전별로 둘 두면 "서비스 하나 → 파드 여러 개" 토폴로지를 보여줄 수 있습니다. 포털의 디플로이먼트 생성 화면 또는 kubectl로 만들 수 있고, msa-b 서비스의 셀렉터(app: msa-b)에 맞춰야 합니다.

항목 값
이름 msa-b-v2
파드 라벨 app=msa-b, version=v2 (두 라벨 모두 필수)
Deployment 셀렉터 app=msa-b, version=v2 (v1 Deployment는 version=v1이므로 겹치지 않음)
이미지 / 포트 harbor.example.com/library/nginx:latest / 80
볼륨 ConfigMap msa-b-conf를 /etc/nginx/conf.d에 마운트

포털 기본 모드 폼이 자체 라벨/셀렉터(예: app=디플로이먼트 이름)를 넣을 수 있어 생성 후 확인이 필요하고, ConfigMap 볼륨이 폼에 없으면 YAML 모드를 사용합니다. YAML은 부록 B에 있고, 같은 내용이 msa-b-v2-305.yaml 파일로도 제공됩니다. 터미널에서 만들려면 kubectl apply -f ~/msa-b-v2-305.yaml 을 실행합니다.

kubectl -n academy get endpoints msa-b
kubectl -n academy get pods -l app=msa-b --show-labels

엔드포인트에 파드 IP가 두 개 보이고 파드 라벨에 version=v1과 version=v2가 있으면 정상입니다. Kiali에서 Graph type을 Versioned app으로 두면 msa-b v1과 v2가 별도 노드로 나뉘어 보입니다.

7. 정리

시연 후 시험 앱과 Gateway를 라벨로 한 번에 삭제합니다. msa-b-v2와 HPA(msa-a-hpa)도 같은 라벨(demo=kiali-msa)이 있으면 함께 삭제됩니다.

kubectl -n academy delete deploy,svc,cm,virtualservice,hpa -l demo=kiali-msa
kubectl -n istio-system delete gateway msa-gateway

academy의 istio-injection 라벨은 시연 후 필요에 따라 원래 값(disabled)으로 되돌립니다.

# 시연용 부하 생성 파드 (VIOLA 3.0.5): 게이트웨이로 일정하게 요청을 보냅니다 (약 2 req/s)
# 중지: kubectl -n academy scale deploy msa-load --replicas=0
# 정리: kubectl -n academy delete deploy msa-load
apiVersion: apps/v1
kind: Deployment
metadata: {name: msa-load, namespace: academy, labels: {app: msa-load, demo: kiali-msa}}
spec:
  replicas: 1
  selector: {matchLabels: {app: msa-load}}
  template:
    metadata:
      labels: {app: msa-load, version: v1, demo: kiali-msa, sidecar.istio.io/inject: "false"}
    spec:
      containers:
      - name: load
        image: harbor.example.com/library/nginx:latest
        command: ["/bin/sh", "-c"]
        args:
        - |
          while true; do
            curl -s -o /dev/null -m 3 -H "Host: okestro-academy-msa-demo.com" http://istio-gateway.istio-system.svc.cluster.local/
            sleep 0.5
          done
        resources: {requests: {cpu: 5m, memory: 16Mi}}

msa_demo_traffic_305.sh

#!/usr/bin/env bash
# Kiali 시연용 트래픽 발생기 (VIOLA 3.0.5)
# 사용법: bash msa_demo_traffic_305.sh [초당요청수=5] [지속시간(초)=180]
#   Ctrl+C 로 언제든 중지할 수 있습니다.
RATE="${1:-5}"
DURATION="${2:-180}"
H=okestro-academy-msa-demo.com
URL=http://192.0.2.48:30223/   # biz-2 노드 IP + istio-gateway 80 NodePort
echo "== 호출 확인 (msa-c ok 가 와야 a->b->c 체인 정상)"
curl -s -m 5 -H "Host: $H" "$URL" || { echo "응답 없음: 시험 앱 상태를 확인하세요"; exit 1; }
echo "== 트래픽 발생: ${RATE} req/s, ${DURATION}초 (Ctrl+C 로 중지)"
