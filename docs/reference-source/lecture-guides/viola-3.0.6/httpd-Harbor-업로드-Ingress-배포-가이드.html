httpd 이미지 Harbor 업로드부터 Ingress 배포까지 절차 가이드

Oct 28, 2026 · @김윤형

개요

Docker Hub의 httpd:2.4 이미지를 사내 Harbor에 올리고, academy 네임스페이스에 Deployment, Service, Ingress를 만들어 http://도메인주소로 접속되게 한 과정을 정리한 문서입니다.

  • 결과: VIP 192.0.2.67에 Host: okestro-academy-httpd-demo.com을 넣어 호출하면 It works! Apache httpd가 응답됩니다.

  • 이미지: edu-harbor.example.com/library/httpd:2.4를 Mac에서 push했습니다.

  • 오브젝트: Deployment httpd(레플리카 1), Service httpd(ClusterIP, 80), Ingress httpd(ingressClassName: istio)를 사용했습니다.

  • 환경: VIOLA 3.0.6 biz 클러스터, Istio ingress, 외부 접속은 HAProxy(80 → 32080) + keepalived VIP 192.0.2.67입니다.

구성도

이미지 경로와 요청 경로 · 2개 경로, 8개 구성요소

이미지는 Mac에서 Harbor로 올리고 노드가 이를 받아 파드를 띄웁니다. 요청은 VIP의 HAProxy에서 istio-gateway와 Service를 거쳐 파드에 닿습니다.

사전 준비

항목 내용
Mac Docker Desktop(인터넷 접속 가능), Harbor library 프로젝트에 push 권한이 있는 계정
클러스터 academy 네임스페이스, kubectl을 실행할 마스터 노드(biz-3)
이미지 저장소 edu-harbor.example.com. 노드에 외부 인터넷이 없고 AlwaysPullImages로 매번 레지스트리에서 받으므로 Harbor에 이미지가 있어야 함
외부 접속 HAProxy가 80을 istio-gateway(32080)로 전달. 도메인 DNS가 없으면 VIP에 Host 헤더로 시험

Harbor에 어떤 이미지가 있는지는 인증 없이 API로 조회할 수 있습니다. 작업 전에는 nginx와 cicd-test만 있었고 httpd는 없었습니다.

curl -sk "https://edu-harbor.example.com/api/v2.0/projects/library/repositories?page_size=50"

절차

순서는 Mac에서 Harbor에 이미지 push → 매니페스트 복사 → 마스터 노드에서 적용 → 접속 확인입니다. 비밀번호는 모두 프롬프트에 직접 입력하고, 명령에 포함하지 않습니다.

1. Harbor에 httpd 이미지 올리기 (Mac)

  1. Harbor가 사설 CA(harbor-ca)로 발급된 인증서를 쓰므로, Docker가 이 레지스트리를 신뢰하도록 CA 인증서를 저장합니다. Harbor가 자신의 CA 인증서를 API로 제공합니다.

mkdir -p ~/.docker/certs.d/edu-harbor.example.com
curl -sk https://edu-harbor.example.com/api/v2.0/systeminfo/getcert -o ~/.docker/certs.d/edu-harbor.example.com/ca.crt

  1. Docker Desktop을 재시작합니다.

  2. 이미지를 받아 태그를 붙이고 로그인한 뒤 push합니다. 아래 스크립트로 한 번에 할 수 있습니다.

docker pull --platform linux/amd64 httpd:2.4
docker tag httpd:2.4 edu-harbor.example.com/library/httpd:2.4
docker login edu-harbor.example.com
docker push edu-harbor.example.com/library/httpd:2.4

--platform linux/amd64는 클러스터 노드가 amd64이라, Apple Silicon Mac에서도 같은 아키텍처로 받기 위함입니다.

  1. push가 끝나면 httpd 저장소와 아티팩트가 생겼는지 확인합니다.

curl -sk "https://edu-harbor.example.com/api/v2.0/projects/library/repositories/httpd/artifacts?page_size=5"

2. 매니페스트 작성

httpd-demo.yaml 하나에 세 오브젝트를 담습니다. 모두 demo: httpd 라벨이 붙어 있어 나중에 한 번에 지울 수 있습니다.

오브젝트 핵심 설정
Deployment httpd 이미지 edu-harbor.example.com/library/httpd:2.4, 레플리카 1, 포트 80, 파드 라벨 app: httpd, version: v1
Service httpd type: ClusterIP, 포트 이름 http, 80 → 80, selector app: httpd
Ingress httpd ingressClassName: istio, 호스트 okestro-academy-httpd-demo.com → httpd:80

Ingress로 접속할 것이라 Service는 ClusterIP면 충분합니다. NodePort는 Ingress를 거치지 않는 별도 접속 경로가 필요할 때만 씁니다. Ingress의 핵심은 다음과 같습니다.

spec:
  ingressClassName: istio
  rules:
  - host: okestro-academy-httpd-demo.com
    http:
      paths:
      - {path: /, pathType: Prefix, backend: {service: {name: httpd, port: {number: 80}}}}

3. 매니페스트 복사와 적용

  1. Mac에서 마스터 노드(biz-3)의 ubuntu 계정 홈으로 복사합니다. scp 비밀번호는 직접 입력합니다.

scp httpd-demo.yaml ubuntu@192.0.2.21:~/

  1. 마스터 노드에서 적용하고 파드를 확인합니다. root로 접속해 있으면 ~가 /root를 가리키므로 경로를 직접 지정합니다.

kubectl apply -f /home/ubuntu/httpd-demo.yaml
kubectl -n academy get pod -l app=httpd

  1. 파드가 ContainerCreating에서 Running으로 바뀔 때까지 약 20초가 걸렸습니다.

4. 접속 확인

도메인 DNS 없이 VIP에 Host 헤더를 직접 넣어 호출합니다.

curl -s -H "Host: okestro-academy-httpd-demo.com" http://192.0.2.67/

It works!가 포함된 페이지가 오면 성공입니다. 브라우저로 http://okestro-academy-httpd-demo.com에 접속하려면 내부 DNS에 이 도메인을 VIP 192.0.2.67로 등록해야 합니다.

트러블슈팅

이번 작업에서 실제로 만난 오류와 조치입니다.

현상 원인 조치
docker login 실패, x509: certificate signed by unknown authority Harbor 인증서가 사설 CA(harbor-ca)로 발급되어 Docker가 신뢰하지 못함. 비밀번호 문제가 아님 Harbor의 getcert API로 CA를 받아 ~/.docker/certs.d/<레지스트리>/ca.crt에 저장하고 Docker Desktop 재시작
재시작 직후에도 같은 오류 데몬이 아직 인증서를 읽지 못한 것으로 추정. 정확한 원인은 확인하지 못했음 재시작이 완전히 끝난 뒤 다시 시도하면 로그인이 성공했음
인증서 검증을 꺼야 하는 경우 CA 배치로 해결되지 않을 때의 대안 Docker Engine 설정의 insecure-registries에 해당 레지스트리만 추가. 이번에는 사용하지 않았음
scp: stat local "httpd-demo.yaml": No such file or directory scp를 실행한 터미널의 현재 폴더에 파일이 없음 파일의 전체 경로를 지정하거나 파일이 있는 폴더로 이동해 실행
error: the path "/root/httpd-demo.yaml" does not exist 마스터 노드에 root로 접속해 ~가 /root인데, 파일은 ubuntu 계정 홈에 올라감 kubectl apply -f /home/ubuntu/httpd-demo.yaml처럼 절대 경로로 지정
파드가 1/1(사이드카 없음) academy의 Istio Injection이 비활성이었을 가능성. 이 파드에 대해서는 설정 상태를 확인하지 못했음 트래픽 모니터링 그래프에 나타내려면 Injection 활성화 후 파드 재생성

Harbor에서 익명으로 manifest를 조회하면 401이 나오는 것은 토큰 인증을 요구하는 일반적인 응답이며, 노드에서의 실제 pull은 정상이었습니다.

정리 및 원복

시험이 끝나면 demo=httpd 라벨이 붙은 세 오브젝트를 한 번에 지우니다.

kubectl -n academy delete ingress,svc,deploy -l demo=httpd
kubectl -n academy get all,ingress -l demo=httpd

Harbor에 올린 library/httpd:2.4 이미지는 지우지 않으면 그대로 남습니다. 필요 없으면 Harbor에서 직접 삭제해야 합니다. Mac의 ~/.docker/certs.d/edu-harbor.example.com/ca.crt는 다른 작업에도 쓰이니 남겨 두셔도 됩니다.
